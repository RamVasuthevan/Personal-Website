My favourite data structure in the Python standard library is the [Counter](https://docs.python.org/3/library/collections.html#collections.Counter). I remember in my first year of university, whenever I was doing a LeetCode-style problem, I would obsessively try to [reduce](https://en.wikipedia.org/wiki/Reduction_\(complexity\)) it—to restructure it, into something that could be trivially solved with a Counter.

Well-written code separates business logic (what the code does) from implementation details (how the code does it). Thus, a good data structure should let the user express its logic clearly while keeping its interface simple. The goal is for the reader to understand what the code does without needing to read the data structure's implementation. A counter is a data structure that tracks the frequency of elements. It can be initialized empty or with initial values (from an iterable).

```repl
from collections import Counter
C = Counter()
C
```

```repl
C = Counter(["Partridge","Turtle Dove","Turtle Dove"])
C
```

We can see the elements:

1. By their frequency:

   ```repl
   C.items()
   ```

2. By their frequency in sorted order

   ```repl
   C.most_common()
   ```

3. All of the elements

   ```repl
   list(C.elements())
   ```

* C.elements() returns an [iterator](https://docs.python.org/3/glossary.html#term-iterator). An iterator is a stream of data whose elements are lazily evaluated. We convert it into a list to see all of the elements in the stream ***Is this correct?***

We can also directly update the frequency of the elements:

1. By setting the frequency of an item:

   ```repl
   C["Calling Bird"] = 4
   C
   ```

2. By incrementing the frequency of an item regardless of it exists:

   ```repl
   C["Gold Ring"] += 5
   C
   ```

**All models are useful, some are useful**

Since Counters are literally a subclass of dictionaries, it's easy to think of them as basically wrappers around dictionaries. It is more useful to think of sets as a special case of Counter, i.e. mutlisets.

A set is an unordered collection of objects. Objects either are not in the set or in the set exactly once. A muliset is a an unorder collection of object but unlike a set, but objects can be memebers of the mutliset more than once.


I was always a bit disappointed that mutliset where not more used more in undgrad math.
